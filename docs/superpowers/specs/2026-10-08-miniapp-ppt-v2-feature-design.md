# 小程序 PPT V2 功能补齐设计

## 背景

参考 `docs/锐音场_决策小程序产品架构与界面概念_v2.pptx`，现有小程序已经具备 84 个蓝图页面、统一聚合接口 `GET /miniapp/screens/{screen_id}`、实体详情页、项目创建、财务测算、证据、风险、门禁、任务、巡演、复盘和账户权限等基础能力。

本次目标不是重新生成小程序，也不是新增一套独立流程，而是在现有页面基础上补齐 PPT 中强调的四类产品能力：

- 首页先证明价值：历史回测、当前机会、快速开始。
- 项目判断形成利润驾驶舱：收益、保本线、资金缺口、组合条件与情景对比。
- “工作”页体现客户专职推进：今日变化、最重要事项、任务派发、证据回收。
- 复盘页形成数据闭环：预测、决策、执行、售票、结算、校准。

## 原则

- 所有新增展示数据必须来自数据库或已有确定性计算，不使用静态假数据。
- 财务测算必须由真实业务参数驱动；参数缺失时显示待补字段，不显示推算结果。
- 用户上传资料和人工事实优先于系统自动补全内容。
- 小程序只连接受控后端，不直连模型、爬虫、数据库或外部连接器。
- 后端继续注入并校验 `tenant_id`、用户身份和权限范围。
- 用户可见文案使用“工作”，内部已有 `agent` provider key、API 标识和代码命名保持不变。
- Taro 源码和原生微信 `dist` 产物必须同步更新。
- 每个新增内容必须有单元测试。

## 范围

### S04：首页价值展示

将 S04 从普通发现页升级为“价值证明 + 当前机会 + 快速开始”的首页。

后端聚合数据：

- `summary.title` 使用业务首页标题，例如“这场演出，值得做吗？”。
- `items` 保留当前机会列表，来源为真实 `Show`、`Project` 或可核验项目版本。
- `options.value_evidence` 返回最多 3 条价值证据：
  - 来源类型：`actual_result`、`historical_backtest`、`verified_case`。
  - 字段：标题、说明、关键指标、来源标签、关联实体上下文。
- `options.quick_start` 返回创建项目所需的最小入口字段提示和目标页 `S13`。
- 无真实数据时返回明确空态，提示创建项目或导入资料。

前端展示：

- 在现有 `BlueprintScreen` 基础上新增首页专属区块，不新增独立页面。
- 顺序为：价值证据、当前机会、快速开始。
- 每条证据必须显示来源标签，避免用户误判为经营事实。

### S11/S25-S32：利润驾驶舱

将项目详情与财务页串成一个可扫描的利润判断区。

后端聚合数据：

- S11 `options.decision_cockpit` 返回当前项目的决策摘要：
  - 中性利润、保本上座率、最大资金缺口、当前结论状态。
  - 当前组合：艺人、城市、日期、场馆、容量、票档、预算。
  - 依据摘要：相似案例数量、待核验报价、待补授权、主要风险。
- S25 返回 `options.finance_cockpit`：
  - 三种情景的收入、利润、保本线。
  - 缺失字段列表。
  - 当前计算所依赖的输入快照。
- S28-S32 继续展示单项情景和敏感性结果，但补充返回统一的驾驶舱上下文字段，便于前端保持一致排版。

前端展示：

- 新增 `DecisionCockpit` 公共展示组件，用于 S11 与 S25。
- 新增 `ScenarioStrip` 展示保守、中性、乐观三种情景。
- 组合字段使用紧凑键值网格，不做营销化大屏。
- 缺参数时显示“待补齐”，不显示结果数字。

### S52/S53：客户专职工作台

将“工作”首页和计划页升级为持续推进视图。

后端聚合数据：

- S52 `options.work_briefing` 返回：
  - 今日变化数。
  - 当前最重要事项。
  - 关联项目名、候选城市数、待确认场馆数。
  - 最近一次系统判断变化及影响金额。
- S53 `items` 保持任务列表，但每个任务补充：
  - `actionability`：可接受、可拒绝、可阻塞、需补证据。
  - `evidence_required`：是否必须提交证据。
  - `due_label`：面向用户的期限文案。
  - `owner_label`：负责人或角色。
- 拒绝、阻塞、完成仍走现有任务接口或批量接口，不在聚合接口中执行写操作。

前端展示：

- 新增 `WorkBriefing` 区块：今日变化、关键判断、最重要事项。
- 任务项增加动作状态标签和证据要求标签。
- S53 继续保留批量选择和批量接受/拒绝能力。

### S64-S66：数据闭环与复盘

将售票进展、实际结果和项目复盘补齐为预测到校准的闭环。

后端聚合数据：

- S64 `options.ticketing_loop` 返回售票阶段信息：
  - 预测销量区间、当前销量、退票、加场或预警状态。
  - 和原预测的偏差。
- S65 `options.actuals_summary` 返回结算输入：
  - 实际收入、实际成本、最终利润、待财务确认字段。
- S66 `options.calibration_loop` 返回复盘校准：
  - 预测利润 vs 实际利润。
  - 预测上座率 vs 实际上座率。
  - 误差原因、改进项、可回流规则。
- 没有真实实际结果时显示复盘空态，不生成结论。

前端展示：

- 新增 `LifecycleTimeline` 展示预测、决策、执行、售票、结算、校准六段状态。
- 新增 `VariancePanel` 展示预测和实际结果差异。
- 所有复盘结论必须带来源字段或负责人字段。

## 数据模型与接口影响

优先复用现有模型：

- `Show`：发现页机会与已完成案例。
- `Project`：项目组合输入、城市、场馆、预算与业务状态。
- `ProjectVersion`：财务测算结果、情景结果、版本差异。
- `Evidence`、`Fact`、`Assumption`、`Risk`、`Gate`：依据链、缺口、风险与人工门禁。
- `Task`：工作计划、负责人、状态、拒绝原因。
- `TourPlan`、`TourStop`：巡演路线和候选城市。
- `TicketingSnapshot`、`ProjectActual`：售票进展、实际成本和结算结果。

如现有字段不足，本轮只允许补充小范围字段：

- `Task.evidence_required`：是否需要提交证据。
- `Task.actionability`：任务允许动作集合或动作类型。
- `ProjectActual.calibration_notes`：复盘误差说明。

字段新增必须同步：

- SQLAlchemy model。
- `schema.sql`。
- 初始化补齐逻辑。
- 后端测试数据。

接口保持兼容：

- 不新增页面路由。
- 不改变 `GET /miniapp/screens/{screen_id}` 的包装结构。
- 不改变现有写接口返回结构。
- 新数据通过 `options` 和 `items[].context` 扩展。

## 前端组件边界

新增展示组件放在 `src/components/ScreenPrimitives` 或同级小组件中，避免把新逻辑重新塞回 `BlueprintScreen`。

- `ValueEvidencePanel`：S04 首页价值证据。
- `DecisionCockpit`：S11/S25 利润驾驶舱。
- `ScenarioStrip`：三情景利润和保本线。
- `WorkBriefing`：S52 工作简报。
- `LifecycleTimeline`：S64-S66 数据闭环阶段。
- `VariancePanel`：预测和实际差异。

`BlueprintScreen` 只负责按 `screenId` 选择展示组件，并传入后端聚合数据。

原生微信生成器同步新增模板片段：

- 首页价值证据片段。
- 驾驶舱片段。
- 工作简报片段。
- 生命周期和偏差片段。

`dist` 仍由 `node tools/generate-wechat-dist.mjs` 生成，不手工编辑。

## 迁移顺序

1. 编写后端聚合测试，覆盖 S04、S11、S25、S52、S53、S64、S65、S66 的新增 `options` 和空态。
2. 实现后端聚合数据，优先复用现有模型和计算结果。
3. 编写 Taro 组件测试，覆盖新增组件的数据渲染、缺字段、空态和点击行为。
4. 实现 Taro 组件并接入 `BlueprintScreen`。
5. 编写原生 runtime/generator 测试，覆盖生成模板里新增区块。
6. 修改原生生成器并重新生成 `dist`。
7. 执行完整回归。

## 验收标准

- PPT 中首页、利润驾驶舱、客户专职工作、数据闭环四个核心价值点均能在现有页面中看到。
- 所有新增展示都有真实数据来源或明确空态。
- 不出现任何演示性质或临时版本性质文案。
- 不新增静态业务结果，不绕过财务参数校验。
- 租户隔离、权限边界、任务写操作边界不变。
- Taro、原生微信和后端测试全部通过。

## 非目标

- 不接入真实外部票务、场馆、审批或爬虫 API。
- 不让大模型修改财务公式、审批门槛、合同权限或租户边界。
- 不重构 84 页状态机。
- 不新增独立首页路由或独立工作路由。
- 不修改微信正式登录的生产配置方式。
