# Agent 计划页项目上下文修复设计

## 问题

S52“今日工作”只返回分配给当前用户的未完成任务。当前数据库中的任务可能全部未分配，因此 S52 没有条目可用于保存项目上下文。用户仍可点击主按钮进入 S53，而 S53 必须携带真实 `project_id`，最终聚合请求返回 422，页面显示“数据加载失败”。

## 目标

- S52 进入 S53 前始终使用当前租户中的真实项目 ID。
- 优先保留用户已经选择或缓存的项目。
- 没有已选项目时，使用当前租户最新的非归档项目。
- 当前租户没有项目时不进入 S53，返回 S10 项目列表。
- 不引入固定项目 ID，不跨租户选择项目。
- Taro 源码与原生微信 runtime 行为一致。

## 后端设计

S52 `agent_dashboard` provider 在原有任务条目之外增加：

- `options.default_project_id`：当前租户最新非归档项目 ID；没有项目时为 `null`。
- `options.available_projects`：当前租户可访问项目的精简列表，包含 `id`、`name`、`status`。

项目按 `id DESC` 排序。provider 不写数据库，不隐式创建项目。

## 前端设计

Taro `BlueprintScreen`：

1. S52 聚合成功后读取 `options.default_project_id`。
2. 仅当本地没有有效 `projectId` 时，将默认项目 ID写入 `STORAGE_KEYS.projectId`。
3. 点击 S52 主按钮时再次解析“已缓存项目或服务端默认项目”。
4. 有项目时进入 S53；无项目时跳转 S10，不发送缺少 `project_id` 的 S53 请求。

原生 runtime 使用相同规则，并由生成脚本重新生成 `dist`。

## 错误处理

- S52 请求失败：保持现有错误和重试状态。
- 默认项目缺失：进入 S10，由真实项目空状态引导创建项目。
- 默认项目不是正整数：视为缺失，不写本地缓存。
- S53 对无效或跨租户项目继续返回 404，不放宽后端权限约束。

## 测试

- 后端：S52 返回当前租户最新非归档项目，不返回其他租户项目；无项目时返回 `null`。
- Taro：没有缓存项目时保存服务端默认项目；已有缓存时不覆盖；无项目时 S52 主按钮跳转 S10。
- 原生 runtime：验证同样的缓存与回退行为。
- 回归：后端聚合测试、前端 Vitest、蓝图 Node 测试和微信构建全部通过。
